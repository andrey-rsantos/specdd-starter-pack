# Knowledge — índice

Conhecimento durável do projeto: o "como funciona na prática" e o "já passamos por isso".
Não entra na ordem de leitura obrigatória — a IA abre este índice quando a task toca um
tema já documentado aqui. Regras de uso: `docs/RULES.md` (§ Base de conhecimento).

## O que vai aqui
- Documentações e guias internos (setup, deploy, rotinas operacionais).
- Integrações externas: como a API/serviço X se comporta de verdade, limites, quirks.
- Problemas conhecidos + workaround (o bug que volta, o erro críptico e a causa).
- FAQs e decisões operacionais que não são regra de negócio nem arquitetura.
- Aprendizados de debugging que economizariam horas na próxima vez.

## O que NÃO vai aqui
- Regra de negócio, contrato ou limite técnico → `docs/SPEC.md`.
- Decisão arquitetural / ADR → `docs/ARCH.md`.
- Task, backlog ou status → `docs/NOW.md`.
- Plano ainda não aprovado → `docs/plans/`.

## Como registrar
- Um arquivo por assunto, nome em kebab-case: `deploy-producao.md`, `api-pagamentos-quirks.md`.
- Comece com 1 linha dizendo o problema que o doc resolve.
- Adicione a linha no índice abaixo no mesmo PR.
